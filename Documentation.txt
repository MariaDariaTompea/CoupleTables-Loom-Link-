% --- CHAPTER 1: INTRODUCTION ---
\chapter{Introduction}
\section{Project Vision}
Maintaining a relationship across vast geographic distances introduces a unique set of challenges, primarily revolving around temporal coordination. ``Loom \& Link'' is a Python-based application designed to bridge this gap by providing a visual, interactive, and ``cute'' scheduling environment. Unlike generic calendar apps, Loom \& Link focuses on the emotional and visual connection between two partners.

\section{Core Objectives}
The primary goals of the system are:
\begin{itemize}
    \item \textbf{Real-time Sync}: Every action taken by one partner is instantly visible to the other.
    \item \textbf{Transparent Localization}: Automated timezone conversion that renders the same event correctly on two different local grids.
    \item \textbf{High Aesthetic Appeal}: Using modern UI principles to create a warm, inviting environment.
    \item \textbf{Simplicity}: A code-based pairing system that eliminates complex email-based invites.
\end{itemize}

% --- CHAPTER 3: TECHNICAL ARCHITECTURE ---
\chapter{Technical Stack}
\section{Frontend: Python with Flet}
The application is built using \textbf{Flet}, a framework that enables the creation of Flutter apps using Python. This allows for a reactive UI that behaves like a native application on both desktop and mobile platforms.

\section{Backend: Supabase Real-time}
To facilitate the sharing of tables, \textbf{Supabase} is employed. It provides a PostgreSQL database with a real-time listener. When Partner A adds an event, the database emits a broadcast, which Partner B's client receives instantly.

% --- CHAPTER 4: THE TIMEZONE ENGINE ---
\chapter{Timezone Synchronization}
\section{The UTC Standard}
To handle users in different regions (e.g., Italy and USA), the application stores all timestamps in the database as \textbf{UTC+0}.

\section{Conversion Algorithm}
When the application fetches an event $E$ with a start time $T_{utc}$, it detects the user's local timezone $TZ_{local}$ and performs the following calculation:
\begin{equation}
    T_{local} = T_{utc} + \text{Offset}(TZ_{local}, T_{utc})
\end{equation}

\section{Day Boundary Logic}
A unique requirement of Loom \& Link is handling events that span across different days for different users. 
For example:
\begin{itemize}
    \item \textbf{Partner A (Rome, UTC+2)}: Adds a ``Movie Night'' on Sunday at 11:00 PM.
    \item \textbf{Partner B (New York, UTC-4)}: The same event occurs at 5:00 PM on Sunday.
\end{itemize}
The engine ensures the event appears on the Sunday column for both. However, if the time difference shifts the event to a Monday for one partner, the app intelligently renders it in the Monday column of the *viewer's* local week.

% --- CHAPTER 5: CORE MODULES ---
\chapter{Application Modules}
\section{Authentication \& Pairing}
The login system uses a simple alphanumeric code ($6 \le \text{length} \le 15$). 
\begin{lstlisting}[language=Python]
def validate_code(code):
    if 6 <= len(code) <= 15:
        return True
    return False
\end{lstlisting}
Once logged in, a user can enter their partner's code to establish a bidirectional link in the \texttt{couples} table.

\section{Event Management}
The event popup allows users to input:
\begin{itemize}
    \item Activity Name (e.g., ``Dinner Date'').
    \item Description (e.g., ``Eating sushi while on FaceTime'').
    \item Color Selection (One of 10 presets).
    \item Start and End Time (converted to UTC before saving).
\end{itemize}
